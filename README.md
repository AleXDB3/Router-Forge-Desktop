# 🌲 Cut2D-2026 — Parametric CNC Routing Studio for Windows

Welcome to **Cut2D-2026**, a lovingly curated companion repository for anyone who believes that a CNC router is not just a machine, but a chisel that speaks in coordinates. This project exists in the orbit of the original Cut2D-2026 concept — a Windows-native 2D routing environment — but takes the idea somewhere warmer, more human, and more habitable for hobbyists, small workshops, and curious makers who want their gantry to move with intention rather than chaos.

Where the original repository focused on the straightforward act of obtaining and setting up the software, this repository expands outward into the surrounding universe: the toolpath philosophies, the material intuition, the shop-floor rituals, and the quiet craftsmanship that turns a flat sheet of plywood into something that outlives the afternoon it was cut.

You do not need a factory floor to benefit from this work. You need curiosity, a spindle, and a willingness to think in two dimensions before you ever commit to a third.

---

## 🧭 What This Repository Really Is

Think of this project as a **field notebook for the routed world**. It is not merely a mirror of an installer page. It is a living atlas of:

- How 2D vector design translates into physical motion
- How Windows-based routing workflows can feel less like software wrangling and more like sketching
- How a single repository can act as both an orientation map and a deep reference shelf for the routing community

The name Cut2D-2026 is deliberate. The **2026** is not a version number in the traditional sense — it is a promise. A promise that the knowledge stored here is aimed at the workshop of the near future, where the boundary between a laptop and a lathe keeps thinning.

## ✨ Feature Highlights

Every feature listed below is described from the perspective of someone standing at the machine, not someone reading a spec sheet.

### 🎛️ Responsive User Interface for Desktop and Tablet
The interface philosophy behind the Cut2D lineage prizes clarity over clutter. Panels reorganize themselves depending on whether you are working on a wide shop monitor or a compact tablet mounted beside the gantry. Your cursor never hunts; your eyes never wander. The layout behaves like a well-organized tool chest — every drawer returns to its resting place.

### 🌐 Multilingual Support Across the Workshop
Routing is a global language, but the software should still speak yours. The documentation and configuration layers described here account for multiple locales, so a machinist in one hemisphere can read the same guide as a machinist in another and feel equally at home.

### 🕓 Always-Available Assistance Around the Clock
Questions rarely arrive on a schedule. Whether you are troubleshooting a pocketing strategy at two in the morning or clarifying a tool library entry during a lunch break, the support model described in this repository assumes that help should be reachable whenever the spindle is humming.

### 📐 Precise 2D Vector Handling
Two dimensions is not a limitation — it is a discipline. This repository treats 2D as a canvas where tolerance, offset, and nesting become acts of respect for the material. You learn to think in contours the way a calligrapher thinks in strokes.

### 🧰 Toolpath Strategy Library
From profile cuts to pocket clearing to V-carving contemplation, the strategies are catalogued with the care of a recipe book. Each one includes the reasoning behind the parameters, not just the numbers themselves.

### 🔁 Reproducible Setups
A cut that cannot be repeated is a lucky accident. Everything documented here is written so that a setup can be reconstructed months later by a different person on a different machine.

### 🪵 Material-Aware Guidance
Wood, acrylic, foam, and composite each ask for a different conversation. The repository includes notes on feeds, speeds, and the intangible feel of a material that is behaving versus one that is about to complain.

### 🧠 Learning-Friendly Architecture
The structure of the folders mirrors the structure of a project: design, prepare, simulate, cut, finish. Beginners can walk the path linearly; veterans can jump straight to the shelf they need.

### 🗂️ Organized Reference Archive
Keywords, jargon, and shop slang are collected and explained so that the vocabulary of routing stops being a barrier and starts being a bridge.

### ⚙️ Windows-Oriented Workflow Notes
Since the originating context centers on Windows 11 and Windows 10 environments, the workflow guidance is tuned for those systems — file management, driver considerations, and the small creature comforts that make a PC feel like a control panel.

### 🔒 Privacy-Conscious Design Notes
The repository documents habits and settings that keep a workshop's data where it belongs: inside the workshop.

## 🧩 The Philosophy Behind the Cuts

A router bit is a rotating question. The material answers. Everything in this repository is an attempt to make that answer more predictable, more repeatable, and more rewarding.

There is a temptation in modern software to hide complexity. This project does the opposite: it *reveals* complexity and then teaches you to befriend it. A pocket is not a hole — it is a shallow theater where the bit performs. An offset is not a number — it is a margin of politeness given to the grain.

These metaphors are not decoration. They are memory aids. When you understand why a toolpath behaves a certain way, you stop copying settings and start composing them.

## 🛠️ Getting Oriented (Without a Single Terminal Command)

The routing world does not require you to live inside a command line, and neither does this repository. Here is how to find your footing:

1. **Start with the mental model.** Read the conceptual overview first. Understand what "2D routing" means when the third dimension is implied by depth rather than modeled in geometry.
2. **Survey the reference shelves.** Each folder represents a stage of the journey. Skim the headings; you will absorb more than you expect.
3. **Pick a single material.** Choose one sheet, one bit, one design. Let the repository guide that narrow slice of experience completely before expanding.
4. **Document your own run.** The best contribution to a community archive is a record of what actually happened in your own shop.
5. **Revisit after the dust settles.** Notes that seem trivial during a cut often become essential the second time around.

There is no rush. A router rewards patience the way a garden rewards rain.

## 🎨 Design Principles

Six principles guide every document in this repository. They are worth stating plainly because they explain almost every decision you will encounter.

**Clarity Before Cleverness.** If a shortcut makes the process harder to explain, the shortcut loses.

**Repetition Is a Feature.** A process that can be repeated identically is more valuable than a process that is merely fast once.

**Respect the Material.** The workpiece is not an obstacle between you and the finished part. It is a collaborator.

**Document the Why.** Numbers without reasoning are rumors. Numbers with reasoning are knowledge.

**Assume a Human.** Every guide is written for a tired, curious, occasionally frustrated person who deserves to succeed.

**Leave It Better.** Every contribution should make the next person's first cut slightly less intimidating.

## 🤝 Contributing to the Workshop

Contributions are welcome from anyone who has stared at a spinning bit and learned something worth sharing. The process is intentionally gentle:

- Open a discussion before a large change, so the shape of it can be considered collectively
- Keep documentation in plain language, as if explaining to a friend across the bench
- Include the reasoning behind any recommended values
- Add a short note about the material and machine context you used
- Be patient during review; everyone here is also mid-project

Small contributions — a clarified paragraph, a corrected diagram description, a better metaphor — are just as valued as sweeping additions.

## 🧪 Testing and Validation Philosophy

Because this repository is knowledge-based rather than purely code-based, validation looks a little different:

- **Conceptual validation** — does the explanation survive contact with a real machine?
- **Cross-machine validation** — does the advice hold on more than one spindle?
- **Beginner validation** — can someone with no prior exposure follow the steps without guessing?
- **Time validation** — does the note still make sense six months later?

If a document fails any of these, it is revised rather than defended.
